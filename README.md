# MD Viewer（mdview）

Windows 上的 Markdown 阅读器和编辑器，可以作为 .md 文件的默认程序。它针对中文（CJK）文档做了优化：中文里的加粗写法、紧跟全角标点的网址、正文排版、GB18030 等中文编码都能正确处理，网页版的搜索也按中文切分。

按[聊天记录格式](#聊天记录格式)书写的 Markdown 文件会显示成聊天视图：头像、气泡、按日期分隔。其他文档中指向某条消息的链接，单击后会在侧边面板里显示这条消息和它前后的消息；也可以一键跳到原文，看完再后退，回到原来的位置。

同一套界面还有[网页版](#网页版nas-或服务器上的-docker)：在 NAS 或服务器上用 Docker 运行，用浏览器阅读和搜索。

## 功能

- **打开方式**：拖放文件或文件夹，命令行 `mdview <路径>[#锚点]`，最近文件，单实例（再次启动时会把要打开的文件交给已经开着的窗口）。
- **界面**：左侧文件夹目录（可筛选），右侧可折叠的大纲（聊天记录按日期列出），标签页，每个标签页都有自己的后退和前进历史。
- **Markdown**：完整支持 CommonMark 和 GFM，包括表格、任务列表、删除线、自动链接、脚注和 GitHub 提示块。另外还支持代码高亮、KaTeX 公式、Mermaid 图表、front matter，以及经过净化的原始 HTML（脚本、表单、iframe 等会被移除）。中文按 markdown-it-cjk-friendly 的规则处理：句号、引号放在 `**` 里面、后面紧接中文正文时也能正常加粗，不会像标准 CommonMark 那样露出星号；网址后面紧跟的全角标点（，。！等）不算进链接。
- **图片和媒体**：本地图片和远程图片都能显示，相对路径、中文路径、含空格或 `#` 的路径、`<…>` 尖括号链接都可以。指向本地图片、视频、语音的链接会直接嵌入成预览。点击图片会全屏查看：再点一下按原尺寸放大（点击处保持不动），放大后可以拖动或滚动查看整张图，再点一下恢复适应窗口；点击周围的暗色区域、× 或按 Esc 关闭。
- **大文件**：几 MB、几万行的文档可以秒开，滚动不卡顿（按块延迟排版）。
- **查找和显示**：Ctrl+F 查找，缩放，浅色和深色主题跟随系统。正文的字号和行距按中文阅读调整；长网址这类不带空格的长字符串也会换行，不会撑宽页面。
- **自动刷新**：文件改动后自动重新渲染，并保持滚动位置。
- **编辑**：工具栏的「阅读 / 编辑 / 并排」切换模式，Ctrl+E 在阅读和编辑之间切换。并排时左边是源文本，右边是实时预览，两边跟着滚动，中间的分隔条可以拖动。编辑器支持 Markdown 语法高亮、撤销重做、查找替换（Ctrl+F / Ctrl+H）。
  - Ctrl+S 保存。保存时沿用文件原来的编码（UTF-8、带 BOM 的 UTF-8、UTF-16、GB18030）和换行符（CRLF / LF）；原文件混用了几种换行符时，统一为其中最多的一种，并给出提示。
  - 有未保存的修改时，标签页显示圆点，窗口标题前有「●」，状态栏显示「未保存」。关闭标签页、在同一标签页打开别的文件、后退前进、关闭窗口之前，都会询问是否保存。
  - 编辑期间文件在外部被改动：没有未保存修改时自动载入新内容；有未保存修改时保留你的修改并显示提示条，可以选择载入磁盘上的版本。保存前会再检查一次，磁盘上的文件和打开时不一样，就先询问是否覆盖，不会悄悄覆盖。
  - 当前内容无法用原编码表示，或原文件里有无法按原编码识别的字节时，保存前会先询问。
- **常用操作**：复制文本、代码或文件路径，在资源管理器中显示，用其他程序打开。

### 聊天视图和消息引用

- 符合[聊天记录格式](#聊天记录格式)的文件默认用**聊天视图**显示：头像、气泡、我的消息靠右，并按日期分隔。图片、视频（带预览封面）、语音会直接内嵌。按 Ctrl+Shift+M 可以切回原始渲染，原始渲染的内容是完整、准确的。
  - 「我」是哪个发送者，由文件开头的 `我：<ID>` 行指明；没有这一行时，会从一对一聊天的文件中自动识别。
- 任何 Markdown 文档中指向某条消息的链接（形如 `[#3](<…/2026-09.md#msg-…>)`，或者 `file:///` 链接）会显示成小标签。单击后，右侧面板会显示目标消息和前后各 4 条消息，可以继续向前、向后展开。
  - 「打开原文」：在当前标签页跳到这条消息所在的文件，并高亮这条消息。之后按 Alt+← 或工具栏的后退按钮，会回到原来文档里的位置。
  - 「新标签」，或者 Ctrl+单击引用：在新标签页打开。
  - Shift+单击引用：不经过侧边面板，直接跳转。
- 目标文件不存在、锚点不存在、媒体文件缺失时，界面会直接说明情况，不会打开空白页。

## 聊天记录格式

聊天视图不需要任何设置，也不要求文件放在特定目录。打开 Markdown 文件时，程序只看文件内容：符合下面格式的就显示成聊天视图，不符合的按普通文档显示。文件是手写的还是由程序生成的都可以。

### 完整示例

```markdown
# 张三 · 2026-09

<a id="msg-a1b2c3"></a>
### 2026-09-01 10:00:00 · 张三 · 文本

发送者：zhangsan · 消息：1

> 早上好
> 今天开会吗？

<a id="msg-a1b2c4"></a>
### 2026-09-01 10:01:05 · 李四 · 文本

发送者：lisi

> 开，十点

<a id="msg-a1b2c5"></a>
### 2026-09-01 10:05:00 · 张三 · 图片

发送者：zhangsan

> \[图片\]

- [图片](../图片/2026-09-01_100500.jpg)

<a id="msg-a1b2c6"></a>
### 2026-09-02 09:30:00 · 张三 · 视频

发送者：zhangsan

> \[视频\]

- [视频](../视频/2026-09-02_093000.mp4)
  - [预览](../视频/预览/2026-09-02_093000.jpg)

<a id="msg-a1b2c7"></a>
### 2026-09-02 09:31:00 · 系统 · 系统消息

> 张三 撤回了一条消息
```

在这个例子里，一级标题的会话名是「张三」，所以另一个发送者「李四」会被识别为「我」，他的消息显示在右侧。

### 怎样才会被识别为聊天记录

文件前 200 KB 内，至少要有一处「锚点行」后面**紧接着**（中间没有空行）一行符合格式的消息标题。满足这一条，整个文件就按聊天视图显示。

### 每条消息的写法

每条消息由下面几部分组成，顺序固定：

| 部分 | 写法 | 要求 | 在聊天视图中的作用 |
| --- | --- | --- | --- |
| 锚点 | `<a id="msg-…"></a>` | 单独一行。`msg-` 后面只能是英文字母和数字，同一个文件里不能重复。 | 标记一条消息的开始，也是引用和跳转的目标。 |
| 标题 | `### 日期 时间 · 发送者 · 类型` | 三级标题，紧接在锚点的下一行。字段之间用「空格 · 空格」隔开。日期写成 `YYYY-MM-DD`，时间写成 `HH:MM:SS` 或 `HH:MM`，两者之间是一个空格。第一个字段是时间，最后一个字段是类型，中间的全部算作发送者，所以发送者名字里可以出现 ` · `。 | 显示头像（名字的第一个字）、名字和时间；日期变化时插入日期分隔线，右侧大纲按日期列出。 |
| 发送者行 | `发送者：<ID>`，后面可以接任意个 ` · 名称：值` 字段 | 可选。必须是标题后的第一段，冒号是全角「：」。第一个 ` · ` 之前是 ID，之后的字段聊天视图中不显示。ID 要稳定：同一个人在所有文件里都用同一个 ID。 | ID 决定头像颜色，也用来识别「我」。没有这一行时消息照常显示，但不会被识别为「我」。 |
| 正文 | 引用块 `> …` | 标题之后的第一个引用块。里面可以有多行、多段和普通 Markdown。 | 显示为气泡。 |
| 附件 | 列表 `- [文字](路径)` | 可选，放在正文之后。 | 显示在气泡下方；指向图片、视频、语音的链接会直接内嵌。 |

其他规则：

- **消息的边界**：一条消息从锚点开始，到下一个锚点、一级或二级标题、分隔线 `---` 为止。可以用 `#`、`##` 给文件分段，这些标题不会被算进消息。
- **一级标题**：第一个 ` · ` 之前的文字是会话名，用来识别「我」，也会显示在引用面板的标题上。后面的部分可以随意写。
- **类型**：`文本` 不显示类型标签；`系统消息` 居中、灰色显示，不显示头像；`图片`、`视频` 消息带有可显示的媒体时，不加气泡底色；其他类型名照常显示，名字后面会加一个类型标签。
- **正文是原始数据**：聊天内容里的 `*`、`_`、`[`、`]`、`` ` `` 等字符应该用反斜杠转义，否则会被当作 Markdown 格式。聊天记录文件中的 `$` 不会被当作公式。
- **原始渲染**：标题和发送者行在聊天视图中隐藏，按 Ctrl+Shift+M 切回原始渲染时会完整显示。

### 图片、视频和语音

- 链接路径相对于这个 `.md` 文件，也可以写绝对路径或 `file:///` URL。路径中的中文、空格可以用百分号编码，或者用尖括号写成 `[文字](<../图片/有 空格.jpg>)`。
- 按扩展名判断媒体类型：
  - 图片：`.png` `.jpg` `.jpeg` `.jfif` `.gif` `.webp` `.bmp` `.svg` `.avif` `.ico`
  - 视频：`.mp4` `.m4v` `.webm` `.mov` `.ogv`
  - 语音：`.mp3` `.m4a` `.aac` `.wav` `.ogg` `.oga` `.opus` `.flac`

  其他扩展名的文件显示为普通链接。其他格式的音视频需要先转换成上面的某种格式。
- 视频封面：在视频链接下面加一个子项，链接文字必须是「预览」，指向一张图片。
- 链接文字没有要求。
- 文件不存在或无法播放时，原位置显示「媒体文件缺失或无法播放」。

### 「我」的识别

程序不需要你填写自己的 ID：

- 文件开头（第一条消息之前）有一行 `我：<ID>` 时，这个 ID 就是「我」。
- 没有这一行时，从一对一聊天的文件中学习：一个文件里恰好有两个不同的发送者 ID，其中一个发送者的名字和一级标题的会话名完全相同，另一个不同，那么另一个 ID 就是「我」。
- 学到的 ID 会保存在设置里（`%APPDATA%\MD Viewer\state.json` 的 `settings.selfIds`），之后对所有文件生效，包括多人聊天。

所以一对一聊天文件的一级标题应该以对方的名字开头，而且对方在消息标题里的名字要和它完全一致。如果只有多人聊天、没有一对一聊天的文件，并且文件里没有 `我：` 行，可以先关闭程序，再把自己的 ID 手动加进 `selfIds` 列表。

### 引用某条消息

任何 Markdown 文档都可以链接到某一条消息：`[#3](<../张三/2026-09.md#msg-a1b2c3>)`，或者 `file:///…/2026-09.md#msg-a1b2c3`。这样的链接显示为小标签，单击后会在侧边面板中显示这条消息和前后的消息。被引用的文件要符合上面的格式，锚点要在行首。

## 安装与运行

需要 Node.js 22 或更高版本。

```powershell
npm install
npm run package          # 生成 out\mdview-win32-x64\mdview.exe
```

`install\mdview-setup.ps1` 用于安装、卸载和创建快捷方式，只作用于当前用户，不需要管理员权限：

```powershell
pwsh -File install\mdview-setup.ps1 shortcut                 # 只在桌面创建指向 out\ 中程序的快捷方式
pwsh -File install\mdview-setup.ps1 install -AddToPath       # 复制到 %LOCALAPPDATA%\Programs\mdview，创建桌面和开始菜单快捷方式，注册 App Paths，并把安装目录加入用户 PATH
pwsh -File install\mdview-setup.ps1 install -Associate       # 额外把本程序加入 .md / .markdown 的“打开方式”列表
pwsh -File install\mdview-setup.ps1 uninstall                # 撤销以上所有改动，删除的文件进入回收站
```

Windows 不允许程序自己把自己设为默认打开方式。使用 `-Associate` 之后，还需要在「设置 → 应用 → 默认应用」中选择 MD Viewer，或者在 .md 文件上使用「打开方式 → 始终使用此应用」。

开发时可以直接运行源码：`npm start`。

## 网页版（NAS 或服务器上的 Docker）

网页版把同样的阅读界面放进浏览器：在 NAS 或服务器上运行一个容器，电脑和手机用浏览器访问。它和 Windows 版共用渲染、聊天视图、消息引用预览、大纲、查找和编辑器，另外提供：

- **多个根目录**：映射到容器 `/roots/<名称>` 的每个文件夹都是目录树里的一个根。默认全部只读。
- **全文搜索**：按消息检索（聊天记录）或按标题分段检索（其他文档），可以限定在当前会话、当前文件夹或某个根，按月份、发送者、消息类型筛选。中文按两个字一组建索引，一个字的查询也能找到。
- **索引保持最新**：容器启动时，以及闲置超过 `MDV_RECHECK_IDLE_HOURS` 小时后第一次有人访问时，后台检查一遍有没有新增、修改、改名或删除的文件；设置了 `MDV_INDEX_SCHEDULE` 时还按时检查（默认不按时检查）。检查只看目录和文件的修改时间，不读内容，有人在浏览时自动让路。检查完成前，搜索结果会把还没核对过的文件现场扫描一遍，并标出「来自扫描」「可能不是最新」。需要搜遍整个范围时，可以放到后台全量扫描，结果保存 7 天。
- **每个文档一个网址**：`/view/<根>/<路径>#锚点`，可以收藏、分享给同一网络里的其他设备；浏览器的后退和前进就是阅读历史。
- **上一个 / 下一个文件**：工具栏的 ‹ › 按目录树里的顺序打开同一文件夹里的上一个或下一个 Markdown 文件。
- **隐藏媒体文件夹**：「更多」菜单里可以打开这个开关，目录树就不再列出只放图片、视频、语音的文件夹（含 Markdown 的文件夹总会显示）。开关状态保存在这台设备上。
- **手机布局**：窄屏时目录和大纲变成抽屉，消息引用预览从底部弹出，搜索全屏显示。
- **打开本机文件**：也可以打开浏览器所在设备上的 Markdown 文件或文件夹，只在这个页面里显示，不会上传。
- **编辑**：Ctrl+S 把编辑后的内容导出为一个副本（「原名（编辑 日期 时间）.md」）下载到本机，原文件不动。要覆盖服务器上的原文件，这个根必须在 `MDV_WRITABLE_ROOTS` 里并以读写方式映射，还要在确认框里逐字输入「我确认用编辑后的内容覆盖 <文件名>」；如果原文件在你编辑期间被改过，覆盖会被拒绝。被覆盖的旧版本保存在状态目录里，每个文件保留最近 5 个。
- **缩略图**：聊天记录里内嵌的图片先显示缩略图（WebP，长边 720 像素），点开全屏查看时才加载原图。缩略图在第一次显示时生成并缓存；长边本来就不超过 720 像素的图片（比如微信的预览图）直接用原图。缓存有大小上限（`MDV_THUMB_CACHE_GB`），超过时删掉最久没看过的。在一个约 147 万张图片的真实归档上测得：约 36.4 万张需要缩略图，平均每张约 26 KB，全部看过一遍约 9 GB。
- **视频**：在 Chrome、Edge 等 Chromium 内核的浏览器（包括手机上的）里，浏览器能解码的视频直接播放；不能解码的（常见于 HEVC），点播放时由服务器转成 H.264 再播放，转好的结果会缓存。容器能用 `/dev/dri`（Intel Quick Sync）时用硬件转码，否则用软件转码；转码不可用或失败时显示原因并提供下载。

### 部署

镜像从仓库根目录构建：

```bash
docker build -f packages/web/Dockerfile -t mdview-web:1.0.0 .
```

基础镜像是官方 Node 镜像（`node:22-bookworm-slim`），默认从 AWS ECR Public 上的 Docker 官方镜像拉取。要改从 Docker Hub 拉取，加上 `--build-arg NODE_IMAGE=node:22-bookworm-slim`。

[`packages/web/compose.example.yaml`](packages/web/compose.example.yaml) 是一个完整示例，把其中的 `<…>` 换成自己的值。需要映射三类目录：

| 容器内路径 | 用途 |
| --- | --- |
| `/roots/<名称>` | 要浏览的文件夹，一个文件夹一个根，建议加 `:ro` 只读映射 |
| `/state` | 搜索索引、设置、登录信息、后台搜索结果、被覆盖文件的旧版本 |
| `/cache` | 缩略图和转码后的视频，可以随时清空。必须是内容目录以外的文件夹：放在某个根里面时，服务器不生成缩略图也不转码 |

文档之间用相对路径互相引用时（比如月报文件夹里的文档引用 `../../聊天记录归档/…` 下的聊天记录），被引用的文件夹要按原来的名字和相对位置映射进来，链接才打得开。两种做法都可以：

- 两个文件夹各映射成一个根，根名和文件夹名完全相同，比如 `/roots/聊天记录月报` 和 `/roots/聊天记录归档`；
- 把同时包含这两个文件夹的上一级文件夹映射成一个根。

根名不同（比如把归档映射成 `/roots/archive`）时，这些引用会显示为找不到文件。

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `MDV_AUTH` | `off` | `on` 时需要密码才能访问。没有设置 `MDV_PASSWORD_HASH` 时，日志里会打印一次性设置码，第一次访问时用它设置密码 |
| `MDV_PASSWORD_HASH` | 无 | 密码的 scrypt 哈希，用 `docker run --rm -i mdview-web:1.0.0 node packages/web/src/server/hash-password.js` 生成（从标准输入读入密码） |
| `MDV_PUBLIC_URL` | 无 | 通过反向代理或隧道以 https 访问时填写对外地址，登录 Cookie 会加上 Secure |
| `MDV_TRUSTED_PROXY` | 无 | 反向代理的地址；只有来自它的请求才读取 `X-Forwarded-For` |
| `MDV_WRITABLE_ROOTS` | 无 | 允许覆盖原文件的根，逗号分隔；对应目录还必须以读写方式映射 |
| `MDV_DISABLE_WRITE` | 无 | 设为 `1` 时完全关闭覆盖原文件 |
| `MDV_RECHECK_IDLE_HOURS` | `24` | 闲置多少小时后，下一次访问时重新检查索引；`0` 表示只在启动时检查 |
| `MDV_INDEX_SCHEDULE` | `off` | 另外按时检查索引：`daily@HH:MM`（每天这个时间，按 `TZ` 的时区）或 `every:<n>h`（每 n 小时）。按时检查会访问内容目录，硬盘会因此被唤醒 |
| `TZ` | `UTC` | 容器的时区，`daily@` 按它计算；中国时间填 `Asia/Shanghai` |
| `MDV_THUMB_CACHE_GB` | `10` | 缩略图缓存的上限（GB），超过时删掉最久没看过的；`0` 表示不生成缩略图，一律用原图 |
| `MDV_TRANSCODE` | `auto` | `off` 关闭视频转码 |
| `MDV_PORT` | `8080` | 容器内监听的端口 |

### 网页版的安全

- 默认不需要登录：能访问这个端口的人都能看到全部内容，所以只应该在自己的局域网里使用。要从外网访问，请设置 `MDV_AUTH=on`，并放在 https 反向代理或隧道后面。
- 服务器只提供映射进来的根目录里的文件：`..`、反斜杠、空段、指向根外的符号链接都会被拒绝。
- 文档里的脚本不会执行，页面受内容安全策略限制。HTML 等可能含脚本的附件只能下载，不会在这个网址下打开。
- 来自其他网站的写操作请求（覆盖、登录、设置）会被拒绝。

## 命令行约定（稳定接口）

```
mdview.exe [<路径>[#锚点] ...] [--anchor <锚点>] [--new-tab] [--folder <目录>]
```

| 参数 | 含义 |
| --- | --- |
| `<路径>` | 要打开的 Markdown 文件。可以是绝对路径、相对于调用方当前目录的路径，或者 `file:///` URL（支持百分号编码）。可以给多个。 |
| `#锚点` | 打开后滚动到这个锚点并高亮。可以是消息锚点 `msg-…`，也可以是标题的 id。只有当整个字符串不是一个已存在的文件时，才会把 `#` 后面的部分当作锚点，所以路径本身含 `#`（例如名为 `#` 的目录）也能正确打开。 |
| `--anchor <锚点>` | 给前一个 `<路径>` 指定锚点。这种写法和路径完全分开，不会产生歧义，**程序调用时推荐使用**。 |
| `--new-tab` | 总是新开标签页。默认情况下，如果文件已经在某个标签页中打开，会切换到那个标签页再定位。 |
| `--folder <目录>` | 把左侧目录树的根设为这个目录。 |

行为约定：

- **单实例**：如果已经有窗口在运行，新启动的进程会把参数交给它，然后在约 0.2 秒内以退出码 0 退出。已有窗口会被激活并打开目标。没有窗口在运行时，会启动新窗口并直接打开目标。
- 这个调用不会等待用户操作。即使文件不存在，退出码也是 0；窗口里会显示「文件不存在」，锚点不存在时会提示「未找到锚点」。
- 不认识的 `--开关` 会被忽略，以兼容 Chromium 自己添加的参数。
- 环境变量 `MDV_USER_DATA=<目录>` 可以让程序使用独立的设置目录和独立的单实例锁，适合测试或便携使用。默认的设置目录是 `%APPDATA%\MD Viewer`。

### 从其他程序调用

建议按以下顺序查找可执行文件：`MDVIEW_EXE` 环境变量 → PATH 中的 `mdview` → `%LOCALAPPDATA%\Programs\mdview\mdview.exe` → 本仓库的 `out\mdview-win32-x64\mdview.exe`。用参数列表启动，不要经过 shell：

```python
import os, shutil, subprocess

def find_mdview():
    for p in (os.environ.get("MDVIEW_EXE"), shutil.which("mdview"),
              os.path.expandvars(r"%LOCALAPPDATA%\Programs\mdview\mdview.exe")):
        if p and os.path.isfile(p):
            return p
    return None

def open_in_viewer(path, anchor=None):
    exe = find_mdview()
    if not exe:
        raise FileNotFoundError("MD Viewer not found")
    args = [exe, str(path)] + (["--anchor", anchor] if anchor else [])
    subprocess.Popen(args, close_fds=True)   # 立即返回；查看器窗口会被激活
```

`mdview.exe "D:\…\2026-09.md#msg-0123…"` 这种写法同样有效。

## 安全与隐私

- 文档中的脚本永远不会执行。原始 HTML 会经过 DOMPurify 净化，页面本身也受内容安全策略（CSP）限制。
- 外部链接会在系统浏览器中打开。打开可执行文件、脚本这类危险文件之前，会先弹窗确认。
- 文档中引用的远程图片会被加载，这和浏览器的行为一致。
- 只有在编辑模式下按保存时才会写入文档，写入的只是当前打开的那个文件。

## 已知限制

- 文件超过 64 MB 时不会打开。
- 单个代码块超过 200 KB 时不做语法高亮。
- 远程图片无法加载时显示为普通的失效图片。
- 视频和语音的播放能力取决于 Chromium 内置的解码器。常见的 mp4（H.264）和 mp3 可以播放；silk 等专有格式的语音不能直接播放，需要先转换成通用格式。
